# Portfolio V2 Design Principles

## 1. Proof Is the Visual Language

Architecture diagrams, system states, code backed interactions, real screenshots, test results, and measurable system behavior should create the sense of sophistication. Decoration should support this evidence rather than compete with it.

## 2. Progressive Technical Depth

Recruiters should be able to scan quickly. Engineering managers should be able to continue deeper into architecture, implementation, tests, and tradeoffs without leaving the narrative.

## 3. Interaction Must Have a Job

Every important animation or interaction should do at least one useful thing: explain a system, reveal evidence, establish hierarchy, improve navigation, or create a memorable identity.

## 4. Personality Without Gimmicks

The site should feel unmistakably personal through language, composition, microinteraction, and engineering concepts. Avoid copying fashionable portfolio effects without a product reason.

## 5. Dense Evidence, Calm Interface

Technical depth can be high while the surface remains legible and calm. Use progressive disclosure rather than presenting every detail at once.

## 6. Accessible by Construction

Keyboard behavior, focus state, contrast, semantics, reduced motion, touch targets, and responsive behavior are part of component design from the beginning.

## 7. Performance Is Part of Craft

A technically impressive portfolio that feels slow undermines its own message. Visual ambition must fit within explicit performance budgets.

## 8. The Portfolio Is a Product

Treat navigation, information architecture, content schema, release quality, analytics choices, deployment, and maintenance as product engineering concerns.
