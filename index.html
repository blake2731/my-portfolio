SmallBizzWizz SaaS Case Study

Financial analytics from messy spreadsheets to operational insight.

SmallBizzWizz is a financial analytics platform for skilled nursing facilities. It ingests spreadsheet exports, validates and normalizes financial records, stores structured reporting data, and generates insight packets and AI-assisted narratives for dashboard review.

Product type
SaaS analytics platform
Domain
Skilled nursing facility finance
My role
Product, full stack engineering, data model, AI workflow
Project Overview

A workflow for turning facility spreadsheets into decision support

The product connects spreadsheet ingestion, data normalization, analytics generation, and narrative reporting into a single authenticated workspace. The goal is to help operators move from raw exports to clear facility-level insights without manually reinterpreting the same data each month.

Business Problem

Financial reporting data often arrives in inconsistent spreadsheet formats requiring significant manual effort to interpret and analyze.

SmallBizzWizz addresses that by validating uploads, mapping rows into normalized records, preserving facility and reporting-period lineage, and producing structured insights that can be reused for dashboard views and AI-generated narratives.

Product Workflow

Upload to analytics pipeline

The core workflow is designed around repeatable financial review: ingest a spreadsheet once, then reuse the normalized data for analysis, insights, and narrative reporting.

  1. 01Upload SpreadsheetFacility exports enter the system as uploaded files.
  2. 02Validate DataProcessing status and diagnostics catch bad or partial inputs.
  3. 03Normalize RecordsSpreadsheet rows become consistent financial records.
  4. 04Store Structured DataFacility, upload, and reporting-period lineage is preserved.
  5. 05Generate InsightsTrends, severity, and supporting metrics are stored.
  6. 06Generate AI NarrativesAudience-specific summaries explain what changed and why.
  7. 07Dashboard ReviewOperators review insights and follow up inside the product.

System Architecture

How data moves through the product

The system separates ingestion, processing, storage, analytics, and narrative generation so uploaded spreadsheets can become reusable reporting data instead of one-off chat context.

Data ingestionSpreadsheet uploads capture file metadata, processing stage, and diagnostics.
ProcessingValidation and normalization convert raw rows into consistent financial facts.
StoragePostgreSQL tables preserve facility, upload, and reporting-period lineage.
AnalyticsInsight packets store trends, severity, thresholds, and supporting metrics.
NarrativesAI-assisted reports transform structured insights into plain-English summaries.
Database Design

Relational model for normalized reporting workflows

The data model was designed to support normalized reporting and reusable analytics. Facility, upload, and reporting-period references appear throughout the analytics tables so each generated insight can be traced back to its source data.

FacilityBusiness unit and tenant boundary for financial data.
UploadSpreadsheet file metadata, processing status, and diagnostics.
ReportingPeriodCanonical reporting month linked to a unique upload.
NormalizedFinancialRecordRow-level financial facts used for analytics.
InsightPacketStructured trends, severity, and supporting metrics.
NarrativeAudience-specific AI summaries tied to source lineage.
